# v0.9.1 Recognition Safety Gate

The quick-solve path must not turn a structurally inconsistent screenshot recognition result into confident game instructions.

Before the Web Worker starts search, the recognized puzzle is checked locally for hard invariants:

- every cup has at most 4 layers;
- every color id is a non-negative integer;
- every detected color occupies a multiple of 4 layers across the puzzle (4, 8, 12, ... are valid);
- every locked/ad cup index points to a detected cup.

If a hard invariant fails, search is stopped before exploring any states. The error returned to the existing quick-solve UI identifies the affected color and all cups that contain it, so the user can re-capture the split-screen image or repair the board in the full editor instead of following an unsafe move sequence.

The known real Android screenshot regression fixture must pass this gate unchanged. The gate is deliberately structural: low confidence by itself remains a review signal rather than a hard failure, avoiding false blocks on valid screenshots with UI chrome or selection outlines.
